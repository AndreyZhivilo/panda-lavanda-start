## Что не так

`CreateOrderUseCase` чистит только `localStorage` (через `cartRepository.clear()`), а кэш React Query `['cart']` не инвалидируется — потому что идёт **в обход** хука `useCart`, в котором и живёт вся логика инвалидации (`invalidate()` в `use-cart.ts:98-99`, навешанная только на собственные мутации хука). Докстринг `use-checkout.ts:35-37` при этом утверждает, что инвалидация происходит — это неверное описание текущего кода.

Следствие: между успехом заказа и следующим refetch в памяти React Query держит старую (неочищенную) корзину. Сейчас это маскируется редиректом на `/` + `staleTime: 0`, но это скрытый баг (например, если убрать редирект).

## Фикс (2 файла)

По архитектурным комментариям хука `useCheckout` — это «React/Query binding». Инвалидация кэша Query — это Query-concern (не бизнес-, не presentation-), поэтому правильное место — `onSuccess` мутации в `useCheckout`, по аналогии с `onSettled: invalidate` в `useCart`.

**1. `apps/web/src/shared/hooks/use-cart.ts`** — экспортировать ключ кэша, чтобы переиспользовать (сейчас он приватный модульный const):
- `const CART_QUERY_KEY` → `export const CART_QUERY_KEY` (строка 28). Имя и `as const` не меняются.

**2. `apps/web/src/shared/hooks/use-checkout.ts`**:
- Импортировать `useQueryClient` из `@tanstack/react-query` и `CART_QUERY_KEY` из `./use-cart` (прямой относительный импорт из соседа, не через barrel — чтобы не плодить лишние связи).
- Получить `const queryClient = useQueryClient()` внутри `useCheckout`.
- Добавить в `useMutation` колбэк `onSuccess: () => queryClient.invalidateQueries({ queryKey: CART_QUERY_KEY })`.
  - Именно `onSuccess`, а не `onSettled`: при провале заказа корзина не трогается, кэш остаётся корректным — рефетч не нужен. На успехе же use-case уже очистил `localStorage`, и инвалидация синхронизирует кэш с пустым хранилищем немедленно (до редиректа).
- Обновить докстринг (строки 32-40): уточнить, что use-case чистит `localStorage`, а хук инвалидирует кэш `['cart']` через `onSuccess` — чтобы описание перестало вводить в заблуждение.

## Почему так, а не иначе

- **Не в use-case:** он чистый TS, ничего не знает про React Query (так и должно быть по Clean Architecture).
- **Не на странице:** инвалидация кэша — не presentation-concern (им является только редирект), её место в Query-биндинге, т.е. в хуке.
- **Не дублировать литерал `['cart']`** в `use-checkout.ts` — переиспользуем единый источник истины (экспортированный `CART_QUERY_KEY`), как и комментируется в `use-cart.ts:24-27`.
- Согласованность с существующим паттерном (`onSettled/onSuccess: invalidate`) — не вводим новую механику.
