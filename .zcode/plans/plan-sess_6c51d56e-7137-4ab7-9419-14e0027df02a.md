# План: Добавление сущности «Категория»

## Контекст и ключевое наблюдение

Значительная часть инфраструктуры **уже существует**:
- `IProduct.category: UniqueId` — поле в домене
- `IProductFilters.categoryId?: UniqueId` — фильтр в домене
- `products.category_id` — колонка в БД (сейчас БЕЗ foreign key)
- Полная цепочка фильтрации по `categoryId`: `HttpProductsRepository` → backend `GET /products?categoryId=` → Drizzle
- В seed-скрипте захардкожены UUID трёх категорий (`CATEGORIES.lavender/shrubs/perennials`)

**Не хватает только:** сущности `ICategory`, таблицы `categories`, репозитория, эндпоинта `/categories` и UI.

Поэтому изменения минимальны и точечно повторяют существующие паттерны (`products` / `orders`).

## Слой 1. Domain (`packages/domain/src/`)

### 1.1. Новый файл `categories/category.ts`
```ts
import type { ImageUrl, UniqueId } from '@panda-lavanda/shared'

/** Каталог растений, группирующий товары (лаванда, кустарники, многолетники…). */
export interface ICategory {
  id: UniqueId
  /** URL-сегмент (`/categories/$categorySlug`). */
  slug: string
  name: string
  /** Необязательная картинка-обложка. */
  image: ImageUrl | null
}
```
Поле `IProduct.category` оставляем как `UniqueId` (без изменений) — задача не требует отображать категорию на карточке товара.

### 1.2. Новый порт `ports/categories-repository.port.ts`
```ts
export interface ICategoriesRepository {
  /** Все категории (их немного — без пагинации). */
  getMany(): Promise<ICategory[]>
  /** Категория по slug или `null`. */
  getBySlug(slug: string): Promise<ICategory | null>
}
```

### 1.3. Экспорты `index.ts`
Добавить:
```ts
export * from './categories'
export * from './ports/categories-repository.port'
```

## Слой 5. Миграция и seed

### 5.1. Генерация миграции
`npm run generate:api` создаст `drizzle/0004_*.sql` с:
```sql
CREATE TABLE "categories" (...)
ALTER TABLE "products" ADD CONSTRAINT "products_category_id_categories_id_fk"
  FOREIGN KEY ("category_id") REFERENCES "categories"("id");
```

### 5.2. ⚠️ Ручная правка миграции (ВАЖНО)
На существующей dev-БД `ALTER TABLE … ADD CONSTRAINT FK` **упадёт**, потому что товары уже ссылаются на `category_id`, которых ещё нет в таблице `categories`. Поэтому после генерации вручную вставляю в `0004_*.sql` **перед** `ALTER TABLE` три строки с фиксированными UUID (теми же, что в seed):
```sql
INSERT INTO "categories" ("id","name","slug","image") VALUES
  ('11111111-1111-4111-8111-111111111111','Лаванда','lavanda',NULL),
  ('22222222-2222-4222-8222-222222222222','Кустарники','kustarniki',NULL),
  ('33333333-3333-4333-8333-333333333333','Многолетники','mnogoletniki',NULL);
```
Это гарантирует валидность FK на любой dev-БД и сразу наполняет таблицу. snapshot/meta/regenerate трогать не нужно.

### 5.3. Обновление `scripts/seed.ts`
- В `TRUNCATE` добавить `categories`: `TRUNCATE TABLE exemplars, products, categories RESTART IDENTITY CASCADE`
- Перед вставкой товаров — вставлять категории (с теми же UUID, slug `lavanda/kustarniki/mnogoletniki`, name по-русски). Порядок важен: categories → products.
- Обновить тексты логов/комментариев про «no categories table».

### 5.4. Применение
`npm run migrate:api` → `npm run seed:api -- --yes`.

## Чего НЕ делаю
- Не меняю тип `IProduct.category` (остаётся `UniqueId`) — не требуется.
- Не делаю категорию у заказа/order_items (там денормализованный snapshot).
- Не добавляю пагинацию к списку категорий (их мало).
- Не делаю админку CRUD категорий (только чтение) — задача требует вывод списков.
- `routeTree.gen.ts` не редактирую руками (генерируется).
