## Diagnosis

The seed script `apps/api/scripts/seed.ts` is **correct** — `parseArgs` (lines 208–229) reads `--count=N` and `buildInsertList` (line 384) builds exactly `count` rows (the 10-entry `CATALOG` is cycled via modulo, not a cap). The "10" you're seeing is `DEFAULT_COUNT` (line 38), which proves `--count=50` never reached the script's `process.argv`.

The flag is being lost in **npm's nested argument forwarding** in npm 10 on Windows: the root scripts end with a trailing `--` (lines 22–24 of `package.json`), and `npm run seed -- --count=50` produces a double-`--` that npm mishandles across the `npm run seed --workspace @panda-lavanda/api --` chain. The flag is swallowed before it reaches `node ... scripts/seed.ts`.

## Fix (root `package.json` only — no changes to `seed.ts`)

Rewrite the three root seed scripts so the workspace invocation uses npm's built-in workspace flag forwarding (`-w`/`--workspace` placed before the script name) and **does not** terminate with a trailing `--`. That way the single `--` you pass on the command line is forwarded intact to `scripts/seed.ts`.

**Current** (`package.json:22-24`):
```json
"seed": "npm run seed --workspace @panda-lavanda/api --",
"seed:api": "npm run seed --workspace @panda-lavanda/api --",
"seed:db": "npm run seed --workspace @panda-lavanda/api --"
```

**Proposed**:
```json
"seed": "npm run seed -w @panda-lavanda/api",
"seed:api": "npm run seed -w @panda-lavanda/api",
"seed:db": "npm run seed -w @panda-lavanda/api"
```

Moving `-w` before the script name and dropping the trailing `--` removes the double-`--` collision. With this, `npm run seed -- --count=50 -y` forwards `--count=50 -y` to the script.
