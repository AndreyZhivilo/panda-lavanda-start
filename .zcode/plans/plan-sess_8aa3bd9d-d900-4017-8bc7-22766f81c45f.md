# Поиск по товарам на странице каталога

Добавляем текстовый инпут поиска, который фильтрует товары по названию (`products.name`, ILIKE). Поисковой запрос (`?q=`) хранится в URL — это позволяет делиться ссылкой, кнопке «назад» работать корректно, а состояние синхронизируется через TanStack Router.

Стратегия: ввод дебаунсится ~300мс, каждый новый запрос сбрасывает страницу на 1-ю.

## Изменения по слоям (снизу вверх)

### 1. Domain — `packages/domain/src/products/product.ts`
Добавить поле в `IProductFilters`:
```ts
/** Поисковый запрос: фильтрация по названию товара (ILIKE). */
search?: string
```
Use case (`get-products.use-case.ts`) менять не нужно — он пробрасывает `IProductFilters` опако.

### 2. Infrastructure — `packages/infrastructure/src/repositories/drizzle-products.repository.ts`
- Импортировать `ilike` из `drizzle-orm` (в существующий импорт).
- В `buildConditions` добавить условие (третий элемент массива):
```ts
filters.search?.trim()
  ? ilike(productsTable.name, `%${filters.search.trim()}%`)
  : undefined,
```
Так как `buildConditions` используется и для items-запроса, и для count-запроса, `total`/пагинация останутся корректными автоматически. Строки `%`/`_` в запросе пользователя экранировать не будем (Postgres ILIKE) — в рамках прототипа допустимо.

### 3. Server function — `apps/web/src/app/server-functions/products/products.functions.ts`
- Добавить `search: z.string().optional()` в `getProductsInputSchema`.
- Передать `search: data.search` в `.execute({...})`.

### 4. Route — `apps/web/src/app/routes/catalog.tsx`
- Добавить `q: z.string().optional()` в `catalogSearchSchema` (как и `page`, опциональный).
- В `stripSearchParams` добавить `q: ''` — пустой запрос не висит в URL как `?q=`.
- `loaderDeps`: `{ page: search.page, q: search.q }` — загрузчик перезапускается при изменении запроса.
- `loader`: `getProducts({ data: { page: deps.page, search: deps.q } })`.

### 5. UI — новый компонент `apps/web/src/shared/components/input.tsx`
Создать shadcn-style Input (параллельно существующему `button.tsx`), используя `cn()` из `@/shared/lib/utils` и `data-slot="input"`. Стандартная разметка shadcn (New York).

### 6. Хук debounce — `apps/web/src/shared/hooks/use-debounce.ts`
Маленький хук (один `useEffect` + `setTimeout`), возвращает дебаунснутое значение. Экспортировать через `apps/web/src/shared/hooks/index.ts`. Реализуем сами, без внешних зависимостей.

### 7. Страница — `apps/web/src/presentation/pages/catalog-page/catalog-page.tsx`
- Импортировать `useSearch` (читать текущий `q` из URL для инициализации инпута), `Input`, хук `useDebounce`.
- Локальный стейт для инпута инициализируется из URL (`useSearch({ strict: false }).q ?? ''`), чтобы при прямом заходе по ссылке `?q=...` поле было заполнено.
- `useDebounce(value, 300)` → `useEffect` вызывает `router.navigate({ to: '/catalog', search: (prev) => ({ ...prev, q: debounced || undefined, page: 1 }) })`. Сброс `page: 1` при новом запросе.
- Поле ввода с иконкой лупы (`lucide-react` `Search`) в `<header>` над заголовком/сеткой.
- Если `q` есть и `products.length === 0` — показать «Ничего не найдено по запросу …» вместо «Товаров пока нет».
- В `goToPage` сохранять текущий `q` (брать из URL) при навигации между страницами.

## Что НЕ меняется
- Use case, composition root, порт репозитория (`IProductsRepository`), DB-схема, DTO `CatalogLoaderData` (форма ответа сервер-функции остаётся прежней).

## Проверка
- `npx tsc --noEmit` в: `packages/domain`, `packages/infrastructure`, `apps/web`.
- `npm run test` (Vitest) — прогнать существующие тесты, убедиться что ничего не сломалось.
- Ручная проверка: ввод → debounce → URL обновляется → список фильтруется → пагинация корректна → сброс страницы при новом запросе → прямой заход по `?q=` заполняет поле.
