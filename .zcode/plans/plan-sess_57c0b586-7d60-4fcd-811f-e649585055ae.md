# Telegram-бот для Panda Lavanda — план реализации

## Зафиксированные решения
- **Фреймворк:** grammy (+ встроенные `session`, `conversations`)
- **Заказы → бот:** Вариант 1 — API сам шлёт в Telegram (порт в domain + adapter в apps/api + хук в `POST /orders`)
- **Фото:** реализовать хостинг в API (`@fastify/multipart` + `@fastify/static`), бот загружает фото через `POST /uploads`
- **Авторизация:** whitelist `TELEGRAM_ADMIN_CHAT_ID` в боте; API пока открыт

---

## Часть 1. Уведомления о заказах (domain + apps/api)

**1.1. Новый порт в domain** — `packages/domain/src/ports/order-notifier.port.ts`
```ts
export interface IOrderNotifierService {
  notifyOrderCreated(order: IOrder): Promise<void>
}
```
- Экспортировать из `packages/domain/src/index.ts` (рядом с другими портами).
- Не reuse `INotificationService` (его контракт — синхронные UI-тосты).

**1.2. Adapter в apps/api** — `apps/api/src/notifiers/telegram-order.notifier.ts`
- `TelegramOrderNotifier implements IOrderNotifierService`
- Использует нативный `fetch` к `https://api.telegram.org/bot<TOKEN>/sendMessage` (grammy здесь не нужен — меньше зависимостей).
- Форматирует `IOrder` в читаемое сообщение (имя, телефон, способ связи, позиции, сумма, время).
- Конфиг через конструктор: `{ botToken, adminChatId }`.

**1.3. Fastify plugin** — `apps/api/src/plugins/notifier.ts`
- Регистрирует `orderNotifier` как decorator (как `dbPlugin`).
- Читает `env.TELEGRAM_BOT_TOKEN` и `env.TELEGRAM_ADMIN_CHAT_ID`.

**1.4. Хук в route** — правка `apps/api/src/routes/orders.ts` `POST /orders`:
```ts
const order = await fastify.ordersRepository.create(body)
// secondary effect — ошибки проглатываются (как cart.clear в use case)
try {
  await fastify.orderNotifier.notifyOrderCreated(order)
} catch (error) {
  request.log.error(error, 'Failed to notify Telegram')
}
return reply.code(201).send(order)
```
- Порядок регистрации plugin: `notifier` после `db`, до routes.

**1.5. Env** — `apps/api/src/env.ts`: добавить
- `TELEGRAM_BOT_TOKEN: z.string().min(1)`
- `TELEGRAM_ADMIN_CHAT_ID: z.coerce.number().int()` (chat id админа-получателя)

## Часть 2. Хостинг фото (apps/api)

**2.1. Локальный file storage adapter** — `apps/api/src/storage/local-file-storage.service.ts`
- Реализует `IFileStorageService` из domain (дублирует ~50 строк из `packages/infrastructure/.../local-file-storage.service.ts` — это сознательно: по правилам архитектуры `apps/api` не импортирует `infrastructure`, имеет свои локальные adapters, как уже делает с repositories).
- Конфиг: `{ storageDir, publicPath }`.

**2.2. Зависимости** — `apps/api/package.json`: `@fastify/multipart`, `@fastify/static`.

**2.3. Fastify plugins/routes:**
- `apps/api/src/plugins/storage.ts` — регистрирует `fileStorage` decorator (создаёт `LocalFileStorageService` из env-путей).
- В `server.ts`: зарегистрировать `@fastify/multipart`, `@fastify/static` (раздаёт `storageDir` по `publicPath`, напр. `/uploads`), `storage` plugin.
- `apps/api/src/routes/uploads.ts` — `POST /uploads` (multipart, image-only): читает file → `fileStorage.save(buffer, ext)` → возвращает `{ url }`. Валидация mime/размера (например jpg/png/webp, ≤5МБ).

**2.4. Env:** `UPLOAD_DIR` (абсолютный путь), `PUBLIC_UPLOAD_PATH` (напр. `/uploads`), `PUBLIC_BASE_URL` (для построения абсолютных URL, напр. `http://localhost:4000`) — опционально, можно возвращать относительные URL и собирать на клиенте.

## Часть 3. Use cases для товаров (packages/application)

Создать (по образцу существующих read-use-cases, через `tryCatch`):
- `packages/application/src/products/create-product.use-case.ts` — `CreateProductUseCase(products, crashReporter?)` → `(data: CreateProductData) => Promise<Either<Error, IProduct>>`
- `packages/application/src/products/update-product.use-case.ts` — `UpdateProductUseCase(products, crashReporter?)` → `(id, data: UpdateProductData) => Promise<Either<Error, IProduct | null>>`
- (Опционально, для точечных изменений цены/остатков) exemplar-level use cases, либо бот вызывает `updateExemplar` через репозиторий напрямую.
- Re-export из `products/index.ts` и `application/src/index.ts`.

## Часть 4. Telegram-бот (apps/telegram-bot)

**4.1. Настройка пакетов:**
- `package.json`: добавить `grammy`, `zod`, `@panda-lavanda/application`, `@types/node` (dev); добавить `imports: { "#/*": "./src/*" }`; скрипты `dev`/`start` с `--env-file-if-exists=.env` (как в apps/api).
- `tsconfig.json`: `"compilerOptions": { "types": ["node"] }`, `"paths": { "#/*": ["./src/*"] }`.

**4.2. Env** — `apps/telegram-bot/src/env.ts` (по образцу apps/api):
- `TELEGRAM_BOT_TOKEN: z.string().min(1)`
- `TELEGRAM_ADMIN_CHAT_ID: z.coerce.number().int()`
- `BACKEND_URL: z.string().url()` (origin API)
- Создать `.env.example`.

**4.3. Composition root** — `apps/telegram-bot/src/app/composition-root/`
- Инстанцирует `HttpProductsRepository`, `HttpCategoriesRepository` из `@panda-lavanda/infrastructure` (конфиг `{ baseUrl: env.BACKEND_URL }`).
- Инстанцирует `CreateProductUseCase`, `UpdateProductUseCase`, `GetCategoriesUseCase`, `GetProductsUseCase` и т.д.
- Хелпер загрузки фото: `POST /uploads` (multipart) к API через fetch → возвращает URL.

**4.4. Bot ядро** — `apps/telegram-bot/src/bot/bot.ts`
- `new Bot(token)`, регистрация `session()` + `conversations()`.
- Admin guard middleware — отбрасывает апдейты от chatId ≠ `env.TELEGRAM_ADMIN_CHAT_ID`.
- Polling для dev (`bot.start()`); production-webhook отмечу как опцию в комментариях.

**4.5. Conversations** (многошаговые flow через grammy conversations):
- `create-product.conversation.ts`: `/newproduct` → выбор категории (inline-кнопки из `GET /categories`) → название → описание → фото (одно или несколько, каждое грузится в `POST /uploads`) → экземпляры (size p9/p11, цена, в наличии; можно несколько) → подтверждение → `CreateProductUseCase` → результат.
- `update-product.conversation.ts`: `/editproduct` → поиск (slug/имя через `GET /products?search=` или список) → выбор поля (цена / остатки / фото / название / описание) → подflow:
  - цена/остатки → `PATCH /products/:pid/exemplars/:eid` (стабильный id);
  - фото → загрузка новых → `PATCH /products/:id { images }` (полная замена массива);
  - название/описание → `PATCH /products/:id`.
- Команды: `/start`, `/help`, `/newproduct`, `/editproduct`, `/cancel`.

**4.6. Форматирование** — `apps/telegram-bot/src/bot/formatting.ts`: хелперы для вывода товара/категории/ошибок.

**4.7. Entry point** — переписать `apps/telegram-bot/src/index.ts`: bootstrap composition root → bot → `bot.start()` + graceful shutdown.

## Часть 5. Wiring и env-файлы

- `package.json` (root): добавить bot в `dev:all` (сейчас web+api).
- `apps/api/.env` и `apps/telegram-bot/.env`: задокументировать новые переменные в соответствующих `.env.example` (TELEGRAM_BOT_TOKEN, TELEGRAM_ADMIN_CHAT_ID, UPLOAD_DIR, PUBLIC_UPLOAD_PATH).
- `docker-compose.yml`: комментарий не трогать (бот на хосте), но можно опционально примонтировать volume под загрузки при контейнеризации API.

## Порядок реализации (по этапам, каждый проверяем отдельно)
1. **Часть 1** — уведомления о заказах → проверить: создать заказ через web → приходит TG-сообщение.
2. **Часть 2** — загрузка фото → проверить: `curl -F file=@img.jpg POST /uploads` → возвращает URL, файл раздается.
3. **Часть 3** — use cases → typecheck.
4. **Часть 4** — бот → проверить: `/newproduct` создаёт товар, `/editproduct` меняет цену/фото.
5. **Часть 5** — wiring (`dev:all`).

## Проверка/типизация
- `npx tsc --noEmit` в `apps/api`, `apps/telegram-bot`, `packages/domain`, `packages/application`.
- Ручной smoke-тест каждого flow через Telegram-чат с реальным ботом (нужен валидный `TELEGRAM_BOT_TOKEN` от пользователя).

## Замечания / риски
- Нужны реальные значения от пользователя: `TELEGRAM_BOT_TOKEN` (от @BotFather) и `TELEGRAM_ADMIN_CHAT_ID` (можно узнать у @userinfobot).
- API остаётся без auth — отмечу в коде TODO на будущее (классы `AuthError`/`PermissionError` уже есть, не используются).
- `LocalFileStorageService` дублируется между infrastructure и apps/api — сознательно (layering); при желании позже вынести в общий пакет, но это нарушит правило «shared без node-deps».
- Загрузка фото в боте: grammy даёт `file_id` → `bot.api.getFile` → скачать → отправить в `POST /uploads`. Это даёт постоянный URL на нашем API (Telegram file_id недолговечен, поэтому копируем к себе).
