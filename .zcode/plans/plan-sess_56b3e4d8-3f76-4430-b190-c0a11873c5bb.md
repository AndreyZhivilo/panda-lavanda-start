## План: страница отдельного товара `/products/$productId`

«Экземпляры товара» в этой кодовой базе называются **exemplars** (`IExemplar`: `size`/`price`/`inStock`) и уже встроены в `IProduct.exemplars: IExemplar[]`. Backend `GET /products/:id` уже возвращает товар со всеми exemplars (404→null), HTTP-адаптер `HttpProductsRepository.getById()` уже реализован. Нужно лишь достроить недостающие слои.

**Дизайн-решения** (по рекомендованным вариантам, т.к. ответов не было):
1. Exemplars — **кликабельный селектор размера** (p9/p11), выбранный показывает цену + бейдж наличия.
2. 404 / null — **inline-сообщение** «Товар не найден» + ссылка в каталог (как в `catalog-page`).
3. `product-card.tsx` — **обернуть в ссылку** на страницу товара (кнопка избранного остаётся отдельным элементом).

### Что НЕ делается (scope guard)
- Не трогаем backend (route уже есть), домен, инфраструктуру (HTTP-адаптер уже есть).
- Не добавляем корзину/«Купить» — кнопка-плейсхолдер опциональна, сейчас опускается.
- Не добавляем маппинг `category` (UUID) → имя категории: в API нет endpoint'а категорий, рендерим только существующие поля товара.
- Не используем `notFound()` из TanStack Router (чтобы не настраивать пока глобальный notFound-компонент) — inline-блок вместо него.

### Проверка после реализации
- `npx tsc --noEmit` в `packages/application` и `apps/web`.
- `npm run generate-routes` в `apps/web` (или через dev-сервер).
- Ручной прогон: страница `/products/<id>` ручная; 404-ветка по несуществующему UUID; ссылка с карточки в каталоге/избранном.
